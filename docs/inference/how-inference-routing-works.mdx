NemoClaw gives agents a managed inference path while OpenShell handles the selected upstream provider on the host.
This design keeps provider credentials outside the sandbox.

## Request Path

Host-local selections for other agents and retained legacy shared-route selections use `inference.local` inside the sandbox.
OpenShell intercepts each request on the host and forwards it to the selected provider.
New Deep Agents Code selections of Ollama, standalone vLLM, llama.cpp, and qualifying host-local compatible endpoints use sandbox-attached providers. Owned Local NVIDIA NIM and retained shared-route selections use `inference.local`.

```text
Sandbox agent -> inference.local -> shared OpenShell route -> selected provider and model
```

NVIDIA Endpoints, OpenAI, Anthropic, Google Gemini, OpenRouter, and Hermes Provider's authenticated hosted endpoint use sandbox-attached native providers.
These selections use the selected provider endpoint instead of `inference.local`.
Explicitly configured Hermes endpoints retain their existing routing behavior.

NVIDIA Endpoints use a sandbox-attached OpenShell provider.
The agent addresses the NVIDIA API hostname, but OpenShell still intercepts the request and supplies the host-managed credential.

```text
Sandbox agent -> integrate.api.nvidia.com -> sandbox-attached OpenShell provider -> NVIDIA
```

Fresh custom hosted endpoints also use a sandbox-attached provider.
Public HTTP and admitted HTTPS IP-literal requests go to the admitted endpoint through OpenShell's credential rewrite.
DNS-backed HTTPS and classified Bedrock requests go through the selected host adapter, which retains TLS or credential custody.
The attachment binds the selected API, endpoint, allowed executables, and issued credential. Ordinary restart verifies and reuses it; existing shared routes are not migrated automatically.

For retained shared routes, host-side services such as Model Router and the OpenRouter runtime adapter remain behind the OpenShell route.
The sandbox uses `inference.local` for those services instead of calling their host ports directly.

## Credential Boundary

Provider credentials stay on the host and flow through the OpenShell provider system.
The sandbox does not receive the raw upstream API key.

Local Ollama and local vLLM routes do not require the host `OPENAI_API_KEY`.
NemoClaw uses provider-specific local tokens for those routes.
For retained shared local routes, rebuilds migrate away from stale OpenAI credential requirements.
Legacy Deep Agents local sandboxes without an attachment require a backup and fresh recreation.
When a rebuild reuses an automatically bridged compatible-endpoint route without a host API key, NemoClaw reapplies the config-only bridge rewrite without reading or passing the credential stored in OpenShell.

## Deep Agents Configuration

For Deep Agents, NemoClaw writes `/sandbox/.deepagents/config.toml` with a managed OpenAI-compatible provider, a scoped placeholder API key, and `use_responses_api = false`. Selections with a native provider attachment use their recorded provider URL and issued credential. Shared-route providers use `https://inference.local/v1`.
New Deep Agents Code selections of Ollama, standalone vLLM, llama.cpp, and qualifying host-local compatible endpoints use sandbox-attached providers. Owned Local NVIDIA NIM and retained shared-route selections use `inference.local`.
The managed `dcode` runtime uses Chat Completions through OpenShell even when a compatible endpoint also supports the Responses API.
