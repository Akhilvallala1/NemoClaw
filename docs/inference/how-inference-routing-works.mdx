NemoClaw gives agents a managed inference path while OpenShell handles the selected upstream provider on the host.
This design keeps provider credentials outside the sandbox.

## Request Path

New NVIDIA Endpoints, OpenAI, Anthropic, Google Gemini, OpenRouter, and Hermes Provider selections use sandbox-attached OpenShell providers.
The agent calls the selected provider's API hostname with a credential placeholder.
OpenShell checks the destination, executable, and allowed request paths, then supplies the host-managed credential.

```text
Sandbox agent -> provider API hostname -> sandbox-attached OpenShell provider -> selected hosted service
```

| Provider | Agent endpoint |
| --- | --- |
| NVIDIA Endpoints | `https://integrate.api.nvidia.com/v1` |
| OpenAI | `https://api.openai.com/v1` |
| Anthropic | `https://api.anthropic.com` |
| Google Gemini | `https://generativelanguage.googleapis.com/v1beta/openai/` |
| OpenRouter | `https://openrouter.ai/api/v1` |
| Hermes Provider | `https://inference-api.nousresearch.com/v1`, or the endpoint returned by authenticated login |

Each sandbox records its selected provider attachment. Changing one sandbox's native selection does not change another sandbox's route.
OpenRouter attribution headers remain in the managed agent configuration.
For an endpoint returned by Hermes login, NemoClaw records its accepted public IP addresses and restricts the provider and sandbox policy to those addresses.
A different destination cannot gain access through a later DNS change.

Eligible new OpenClaw and Deep Agents Code local selections, including qualified host-local `compatible-endpoint` routes, use sandbox-attached OpenShell providers. Each provider profile restricts the destination, request paths, executable, and endpoint-bound credential. Local NVIDIA NIM remains on `inference.local` while NemoClaw pins OpenShell 0.0.116, as do user-supplied endpoints that do not qualify for native attachment, Hermes local selections, Model Router, and existing shared-route sandboxes.

OpenClaw and Deep Agents Code local sandboxes that require native attachment cannot resume or rebuild on an older shared route without that attachment. NemoClaw stops at resume or rebuild preflight, before changing the sandbox. Back up the sandbox, then re-onboard with `--fresh --name <name> --recreate-sandbox` to attach a native provider. Local NVIDIA NIM retains its shared route and can resume or rebuild on the pinned OpenShell release. OpenShell 0.1.0 and later remove `inference.local`, so complete native replacement and migrate or retire Local NIM and the remaining custom, Hermes local, and Model Router shared routes before upgrading OpenShell. This release does not migrate any of them automatically.

```text
Shared-route agent -> inference.local -> OpenShell gateway -> selected provider and model
```

Use `$$nemoclaw inference get` to inspect the selected sandbox's recorded route.
`status`, `doctor`, and startup checks verify its recorded native provider identity before using a native attachment.
Missing or conflicting ownership stops the operation instead of falling back to the shared route.

## Credential Boundary

Provider credentials stay on the host and flow through the OpenShell provider system.
The sandbox does not receive the raw upstream API key.

Local Ollama and local vLLM routes do not require the host `OPENAI_API_KEY`.
NemoClaw uses provider-specific local tokens for those routes.
Eligible new native-local selections use endpoint-bound credentials without a host `OPENAI_API_KEY`.
When a rebuild reuses an automatically bridged compatible-endpoint route without a host API key, NemoClaw reapplies the config-only bridge rewrite without reading or passing the credential stored in OpenShell.

## Deep Agents Configuration

For Deep Agents, NemoClaw writes `/sandbox/.deepagents/config.toml` with a managed OpenAI-compatible provider, a scoped placeholder API key, and `use_responses_api = false`. Native hosted selections use the endpoints above; eligible new local selections use the qualified host-local endpoint from their attached provider. Local NVIDIA NIM, existing shared-route sandboxes, and other custom selections use `https://inference.local/v1` while running on OpenShell 0.0.116.
The managed `dcode` runtime uses Chat Completions through OpenShell even when a compatible endpoint also supports the Responses API.
